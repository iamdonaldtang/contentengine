## 1 · 公网 2 子域可达性（30s）

```powershell
# Donald 笔记本 PowerShell

curl.exe https://ingest.taskon.xyz/health
# 期望: {"service":"taskon-ingestion","status":"ok"}

curl.exe https://l.taskon.xyz/rest/v3/health
# 期望: {"status":"pass","version":"5.0.2",...}
```

**两个都 200** = CF Tunnel + DNS 已经切到服务器笔记本上的 cloudflared ✅

如果 502 / Could not resolve：服务器笔记本上 cloudflared service 没起，或者运维忘了配 Public Hostnames。回去看完整版手册 §10 排错。

## 2 · CORS preflight（30s）

```powershell
curl.exe -X OPTIONS https://ingest.taskon.xyz/api/landing-signup `
  -H "Origin: https://taskon.xyz" `
  -H "Access-Control-Request-Method: POST" `
  -H "Access-Control-Request-Headers: content-type" `
  -i | Select-String -Pattern "Access-Control"
```

**期望 3 行**：

```
Access-Control-Allow-Origin: https://taskon.xyz
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Credentials: true
```

如果没有这 3 个 header：服务器笔记本 ingestion 容器**没读到** `.env` 里的 `CORS_ALLOWED_ORIGINS`。让服务器笔记本侧跑一次 `docker compose restart ingestion`。

## 6 · 停 Donald 笔记本旧 cloudflared service（避免冲突 · 30s）

**重要**：旧 cloudflared 还跑着会有概率被 CF 路由到 · Donald 笔记本上没 engine 容器 → 50% 502。

```powershell
# Donald 笔记本 · 管理员 PowerShell

# 1. 停
Stop-Service cloudflared

# 2. 禁用开机自启
Set-Service cloudflared -StartupType Disabled

# 3. 验证停了
Get-Service cloudflared
# 期望: Status: Stopped, StartType: Disabled
```

跑完这步后再去重测一遍 §1 + §3（确保停旧 cloudflared 没影响公网链路）。

## 7 · 哨兵脚本搬迁（5min）

V1 上线时写的 `scripts\watch_tunnel_health.ps1`（每 5min 巡检 cloudflared + ingest + l）现在跑在 Donald 笔记本上 · 但它检查的是**本机 cloudflared service** · 在 Donald 笔记本上已经停了 · 会一直报错。

### 7.1 · 停 + 删 Donald 笔记本上的旧哨兵任务

```powershell
# Donald 笔记本 · 管理员 PowerShell
Unregister-ScheduledTask -TaskName "TaskOn-TunnelHealth" -Confirm:$false
# 期望: 无输出 (或显示 "Removed")

# 验证
Get-ScheduledTask -TaskName "TaskOn-TunnelHealth" -ErrorAction SilentlyContinue
# 期望: 无输出 (任务已删)
```

### 7.2 · 把脚本 + 注册任务搬到服务器笔记本

服务器笔记本上跑（远程 RDP 或 Tailscale SSH 进去跑）：

```powershell
# 服务器笔记本 · 管理员 PowerShell

# 1. 确认脚本在 (V1.1 之前应该已经从 git/Donald 同步过来了)
ls D:\Taskon\marketing\engine\scripts\watch_tunnel_health.ps1
# 期望: 文件存在

# 2. 注册成 Scheduled Task (脚本自带 -InstallScheduledTask)
cd D:\Taskon\marketing\engine
.\scripts\watch_tunnel_health.ps1 -InstallScheduledTask

# 3. 验证
Get-ScheduledTask -TaskName "TaskOn-TunnelHealth"
# 期望: State: Ready
```

## 10 · 常见问题快查

| 现象 | 原因 | 修复 |
|---|---|---|
| `curl ingest.taskon.xyz/health` 502 | 服务器笔记本 ingestion 容器没起 | 那边跑 `docker compose up -d ingestion` |
| `curl ingest.taskon.xyz/health` Could not resolve host | DNS 还没生效 / 运维 Public Hostname 没配 | 等 30s 重试 / 让运维确认 |
| 浏览器看到旧错误页 | 缓存 | Ctrl+Shift+R 硬刷新 |
| CORS preflight 缺 Access-Control-Allow-Credentials | 服务器笔记本 ingestion 没读到 `.env` | 那边 `docker compose restart ingestion` |
| Lark 群没收到 | LARK_WEBHOOK_URL 没复制到服务器笔记本 .env | 检查那边 .env · 重启 ingestion |
| Postiz UI 超时 | Postiz 容器 ports 没 0.0.0.0 / Win 防火墙 | 那边 `docker compose ps` 看 ports |
| Tailscale SSH 进不去 | sshd 没装 / Tailscale SSH 没启用 | 完整版手册 §7 |
