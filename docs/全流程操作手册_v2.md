# TaskOn 内容流水线 · 全流程操作手册 v2（2026-05-21 起生效）

> **本手册定位**：把内容「选题 → 起草 → 审稿 → 数据关 → 多平台改写 → 排程 → 真发 → 数据回流」做成**一条可随时启动、随时跑完的线性流水线**。
>
> **跟 v1 的根本区别**：v1（`Cowork启动手册.md` / `Donald_每日操作手册_v1.md` / `B1流程跑通_首次执行指南.md`）是**按周排的日历**——周日选题、周一起草、周三 09-12 终审 3h、周四发布。v2 **取消日历**：一条 piece = 一次从头到尾的流程，你想跑就跑，跑一次出一条。
>
> **核心目标**：你可以在 **2 小时内、甚至更短**把流水线从头完整跑完一次；数据轻的 piece 可做到**每小时跑一条**；生产端不设产量上限。
>
> **engine 现状前提**（沿用 2026-05-19 W22-W24 ship 状态）：249/249 pytest 全绿 · Postiz LinkedIn + YouTube 2 个 integration 已通 · MPT 视频渲染就位 · shlink 短链跑着 · async webhook + `{{CTA_URL}}` 占位符就绪。X / Medium / TikTok 未连，自动 skip（不阻塞）。

## 0 · v2 相比 v1 改了什么（必读）

| 变化 | v1（旧） | v2（新） |
|---|---|---|
| **节奏** | 按周排日历：周日选题 / 周一起草 / 周二评审 / 周三终审 / 周四发布 | 取消日历。一条 piece 端到端线性跑一遍，随时启动 |
| **终审** | 周三 09-12 固定 **3 小时**仪式，是红线 | **取消 3h 红线**。拆成「审稿」+「数据关」两个独立步骤，**都不限时**——快则十几分钟，慢则按需，做完即过 |
| **选题来源** | 周日 cron `kol_watch` + `topic_ranker` 出 Top10 | **每次跑现抓**：Cowork 跑 `crypto-news-aggregator` 拉 7 天热点 → 你当场挑 1 条 |
| **配图** | 兼职女生周一/二用 Canva 按周配图（阻塞主线） | **改 AI 生成 + 异步支线**，不阻塞主线。你仍审图 |
| **短视频** | 周一 11:00 cron 渲染 | 任意时刻提交，async submit-and-exit，异步支线 |
| **保留不变** | — | 你审起草、你审配图、你核数据、engine 永不自动发推/DM、`{{CTA_URL}}` 占位符红线 |

**一句话**：v2 把「一周一批」拆成「一次一条、按需连跑」。主线关键路径 ≈ 60 分钟；配图和短视频改成异步支线，所以你跑完主线就能立刻开下一条，不用等图、不用等视频。

| 角色 | 在 v2 里负责 |

## 2 · 全流程 13 步总览

> **piece_id 约定**：v2 用日期 + 序号，例：今天第 1 条 = `20260521-01`，第 2 条 = `20260521-02`。下文命令统一用 `<piece-id>` 占位。

| 0 | 入场检查 | Cowork | 主线 | 0.5 min |

### 步骤 4 · 审稿 + 可选辣评质检 〔你 + Cowork · 不限时，通常 ~10 min〕

> **这是你保留的人工检查点之一（你说过「起草我还是会看的」）。不限时——快则几分钟，按需即可。**

**4.1 · 你审稿**。让 Cowork 念给你：

```
把 piece 20260521-01 念给我审：
- xthread_final.md（X 终稿）
- linkedin_post.md（B2B 版抽查）
- voice_report.md：14 禁词有没有过 + 末尾 ## Algorithm Rules 段是 PASS 还是 FAIL
```

你审的是：**角度对不对 / 钩子够不够狠 / 读起来像不像人话 / 利益披露有没有 / 可操作性**——把自己当客户读一遍，能回答"明天第一步做什么"= 过。

- `voice_report` 出现 `state=needs_revision`（禁词）→ 让 Cowork 改稿后重跑 `voice_checker`。
- `Algorithm Rules: FAIL`（推 1 含外链）→ 把 URL 移到 thread 第 2 条自我 Reply。

**4.2 · 可选 · 辣评质检**（想多一道客观分时）：

```
跑 taskon-content-critic 对 piece 20260521-01 的 X Thread 评分，
读 xthread_final.md，输出 10 维 50 分 + 3 处改写 + 标题候选 3 条 + CTA 重写，
落到 runtime/drafts/20260521-01/critic_report.md，念给我。
```

参考阈值：≥45 直接过 / 40-44 改 1-2 项 / <40 考虑砍。这是**参考**，不是红线——你说了算。

### 步骤 5 · 数据关（独立步骤）〔你 · 不限时〕

> **保留为独立步骤，但去掉 3h 死线。** 核完即过——可能 10 分钟，可能 1 小时，取决于这条有几个新数字。这是品牌安全的最后一道闸。

```
把 piece 20260521-01 里所有标了 [SOURCE: xxx] 的数字列出来，
每个数字旁边附它的来源链接，我逐个点开 DefiLlama / Dune / 内部 dashboard 比对。
```

你逐个核：每个数字打开来源比对。**全对 → 过；任一对不上 → 这条死了，砍。**

**通过**：

```
piece 20260521-01 数据关通过，标 state=reviewed：
bash:
docker compose exec engine python -c "from lib.db import db; db.execute('UPDATE pieces SET state=\"reviewed\" WHERE id=?', ('20260521-01',)); db.commit()"
```

**失败（砍）**：

```
piece 20260521-01 数据关失败（第 X 推数字与来源不一致），标 state=killed 不发：
bash:
docker compose exec engine python -c "from lib.db import db; db.execute('UPDATE pieces SET state=\"killed\" WHERE id=?', ('20260521-01',)); db.commit()"
```

> **★ 红线（保留）**：数据关失败 = 砍。**绝不允许让 AI 改数字**。engine / Cowork 可以帮你列来源、帮你算，但比对和拍板是你的。

### 步骤 6 · 配图（AI 生成）〔Cowork 生成 + 你审图 · 异步支线〕

> **异步支线**——在步骤 3 之后任意时刻都能并行启动，**不阻塞步骤 7-12**。你仍然审图（你说过「配图我还是会看的」），但审图发生在主线之外，图好了再看。

```
为 piece 20260521-01 用 AI 生成配图，落到 runtime/drafts/20260521-01/assets/：
- X / LinkedIn 主图：把核心数字做成一张数据图
- Carousel：10 页视觉
- YT Shorts 首帧
风格走 TaskOn 品牌调性，生成完念一遍给我审。
```

你审图：构图、数字标注、品牌感对不对。不满意让 Cowork 重生成。

**为什么不卡主线**：Postiz 在**真正发布的时刻**才去拉媒体（错峰发布给了几小时到几天的缓冲）。所以图只要在该平台的发布时点前落到 `assets/` 就行——你完全可以先把主线（步骤 7-12）跑完、真发排程，配图在背景里慢慢出。

> 若某条要发布得很急、图还没好 → 先发文字版，图后补。生产端不因为等图而停。
> 配套：此步依赖 Cowork 侧的 AI 生图能力（imagegen skill 或已连的生图工具）。若暂未接通，回退到兼职女生 Canva 出图——但仍按「异步、不阻塞主线」处理。

### 步骤 7 · 短视频渲染 〔engine · 异步支线〕

> **异步支线**——步骤 3 出了 `shorts_60s.md` 之后任意时刻可提交，submit-and-exit < 1 秒返回，**不阻塞主线**。

```
提交 piece 20260521-01 的短视频渲染：

```

YT Shorts 默认错峰排在最后，渲染时间窗充裕；不必等视频跑完才继续主线。

## 4 · 时间预算：2 小时怎么跑完 / 每小时怎么跑

**关键路径耗时**（一条 piece，从头到真发）：

```
步骤 0  入场检查        0.5 min   Cowork
步骤 1  抓热点+选题      5-10 min  Cowork 抓 + 你挑
步骤 2  起 X 主稿        5-15 min  Cowork
步骤 3  4 平台改写       2-3 min   engine
步骤 4  审稿            ~10 min   你（不限时）
步骤 5  数据关          10-30 min 你（不限时，按数字量）
步骤 8  UTM            1 min     engine
步骤 9  YT 元数据        3-4 min   Cowork + 你
步骤 10 Custom Slice    2 min     engine（可跳）
步骤 11 dry-run         1 min     engine
步骤 12 真发            1 min     engine（+ 你手发 X ~5 min）
————————————————————————————————
关键路径合计 ≈ 45-85 min   →  2 小时内跑完有富余
```

**异步支线不算在关键路径里**：步骤 6 配图、步骤 7 短视频在步骤 3 之后并行启动，在背景里跑，**主线不等它们**。它们只要在各自平台的发布时点前完成即可（错峰给了几小时到几天缓冲）。

**每小时跑一条怎么做到**：
- 主线大头是你的两个人工步骤（审稿 + 数据关）。议题选**数字少、或复用已核对过数据**的，数据关能压到 10 分钟内，整条 ≈ 40-50 min → 每小时一条可行。
- 数字密集的深度稿，数据关本身可能超过 1 小时——这种 piece 别硬塞进「每小时」节奏，单独安排。**这是 v2 唯一诚实的限制**：数据关不限时也不偷工，它的耗时就是它的耗时。
- 因为配图/短视频是异步的，你跑完 piece A 的主线就能立刻开 piece B，A 的图和视频在背景里继续。**多条 piece 可同时在飞，engine 各自独立处理。**

**无人值守的边界**：v2 仍有 4 个你必须在场的动作（选题、审稿、数据关、审图）。真正的全自动无人值守做不到——但「2 小时一条」「忙起来每小时一条」「想跑就跑、不用等周日」这三个目标 v2 都给你了。

---

## 5 · 生产不设限 vs 错峰发布

这两件事 v2 分开处理，互不打架：

- **生产端不设上限**：步骤 1-12 产出 piece 的过程没有配额、没有「一周几条」的限制。你想连跑就连跑，想每小时一条就每小时一条。多条 piece 并行在飞。
- **发布端保留错峰**：`schedule_planner` 仍把**单条 piece 的多个平台**按错峰铺开（LinkedIn Post → Carousel → YT Shorts 间隔 24h+），避免同一条内容在多平台同时砸、互相抢量、触发算法识别。
- **多条 piece 之间互不挤压**：每条 piece 各自独立错峰，engine 按各自的 `scheduled_at` 排。你今天跑了 5 条，就是 5 条各自错峰的发布计划叠在日历上，不会因为「这周已经发过了」被压下去。
- **要立刻发**：单条想绕过错峰马上发，用紧急路径 `POST /admin/run_publish`（`offset_minutes` 设小值）。

## 6 · v2 红线（精简版）

v1 有「7 个不可让渡时刻 + 3h 终审」。v2 砍掉日历和 3h 死线后，**真正的红线只剩这几条**：

1. **数据关失败 = 砍**。绝不允许让 AI 改数字。（步骤 5）
2. **engine 永不自动发推 / 自动 DM**。X Thread、KOL Reply、KOL DM 都你手发。
3. **所有平台文案 + yt_metadata description 必须含 `{{CTA_URL}}` 占位符**，不写真实 URL（归因断链风险 R17）。
4. **选题拍板必须你来**（品牌方向决策）。

**保留的人工检查点**（不是红线，但你说过要看，v2 给你留着）：审起草稿（步骤 4）、审配图（步骤 6）。

**明确不再是红线/不再要求的**：固定 3h 终审时长、按周排的日历、周一/二/三的固定分工。

这些 cron 继续在后台跑，跟 v2 主线无关，你不用管：

✅ 每日 23:00 · backup_sqlite（保 14 天）
